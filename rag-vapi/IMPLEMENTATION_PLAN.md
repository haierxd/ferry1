# v-api pgvector MySQL RAG 实施计划

目标与设计以本次用户需求为准：独立 Node.js 实现；不引入 RAG 框架；资料只通过显式执行 ingest 发给 v-api。

1. 配置与嵌入：显式 baseURL 和模型，拒绝直连 OpenAI，1536 维强检查，输入长度保护。
2. 知识管线：按一级二级标题和 400–800 字分块；按文件事务替换；唯一索引和模型配置校验；失败继续报告。
3. 检索：模型配置一致性校验，参数化余弦 top-k，强制知识根目录范围。
4. API：验证 JWT 的 sub 与 MySQL 用户；普通/SSE 回答；完整结束后保存 conversations；失败和断流不保存半条答案。
5. 交付：全量与增量 SQL、环境示例、运行命令、测试和模型属性/出网边界说明。

测试使用 node:test、可控的 SDK/数据库替身和本机 HTTP 服务，不带真实凭据，不向 v-api 发送资料。
测试重点为块长及正文保留、维度不符、配置不一致、事务回滚、参数化检索、鉴权、SSE 完成后入库与失败不入库。
保持现有 server、SQL 和所有真实 .env 不变；新项目仅位于 rag-vapi。
